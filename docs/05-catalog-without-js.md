# 5. Каталог мастер-классов существует только в JS

**Статус:** не сделано · **Влияние:** высокое (видимость контента и для робота, и для человека) · **Риск:** средний

## Постановка

Две разные поломки в одном месте.

**а) Каталог рендерится скриптом.** В `index.html` контейнер пустой:

```html
<div class="workshop-grid" id="cards">   <!-- внутри ничего нет -->
```

21 мастер-класс лежит в `assets/js/main.js` как литерал `const workshops` (20 записей)
плюс один `workshops.push({...})` (курс по академическому рисунку) — итого 21 карточка,
и все они появляются только после `render()` (`main.js:23`, `cards.innerHTML = ...`).

Поисковый робот, не исполняющий JS, видит пустую секцию «Мастер-классы» — то есть
**коммерческое предложение сайта отсутствует**. Поисковики индексируют JS-контент
с задержкой и не всегда; для локального бизнеса это прямой риск.

**б) `.reveal` прячет контент до JS.** 28 элементов с `class="... reveal..."` имеют
`opacity:0;transform:translateY(22px)`, а `.visible` навешивает `IntersectionObserver`
(`main.js:83`). Вызовов `noscript` в файле — **0**.

Значит при любой ошибке в `main.js` (например, удалённый или переименованный элемент:
`getElementById(...)` вызывается повсюду без проверок на `null`) страница остаётся
визуально пустой — герой, «О мастерской», контакты. Это не теоретический риск:
один `TypeError` обрывает весь скрипт.

## План реализации

### Шаг 1. Единый источник данных, а не две копии

Сейчас данные в JS-литерале. Если просто дописать статические карточки в HTML, правку
«мастер-класс» придётся делать в двух местах. Поэтому:

1. Вынести датасет в `assets/data/workshops.json`.
2. Новый генератор `tools/build-catalog.py`: из JSON делает **и** статические
   `<article>` в `#cards`, **и** минифицированный `assets/js/catalog.js`
   (то же окно `window.WORKSHOPS`, чтобы фильтры не переписывать с нуля).
3. Источником истины остаётся JSON; `main.js` больше не содержит литерал.

### Шаг 2. JS — только улучшение, не условие видимости

- `render()` перестаёт перерисовывать `innerHTML` с нуля. Фильтры (`#filters`,
  `data-filter`) переключают видимость готовых карточек по `data-category`
  (класс/`hidden`), а не генерируют разметку.
- Побочный выигрыш: сегодня при смене фильтра `innerHTML` пересоздаёт 21 карточку →
  картинки-`<picture>` грузятся заново. С скрытием этого не будет.

### Шаг 3. Фолбэки для `.reveal`

- Маленький инлайн-скрипт в `<head>` ставит `document.documentElement.classList.add('js')`.
- CSS: `.reveal{opacity:0…}` действует только внутри `html.js` → без JS контент видим.
- Дополнительно `<noscript><style>.reveal{opacity:1;transform:none}</style></noscript>` —
  на случай, когда JS отключён, но инлайн-скрипт тоже не выполнился.
- Добавить `try/catch` вокруг инициализации или null-проверки, чтобы одна потерянная
  кнопка не обрывала обработчик observers (сейما один `TypeError` = пустая страница).

### Шаг 4. Проверить цену

Статические 21 карточка — это ~30–40 КБ HTML до gzip. Замерить после генерации;
страница сейчас 36 КБ, ожидается рост до ~70 КБ raw / ~15 КБ gzip — при экономии
в 20 МБ на картинках это несущественно, но цифру надо знать.

## Критерии приёмки

- `curl -s https://домен/ | grep -c 'work-card'` = 21 (контент в исходном HTML).
- В Chromium с полностью отключённым JS: видны 21 карточка и все секции,
  ничего не осталось с `opacity:0` (замер `getComputedStyle` по всем `.reveal`).
- Фильтры по-прежнему фильтруют; клик «Подробнее»/«Записаться» работает как сейчас.
- Регресс-набор диалогов (`test-lock.mjs`) остаётся зелёным.
- Снимок страницы до/после совпадает (методика: отключённые анимации, принудительный
  `eager`, контрольная пара одной версии даёт 0 различий).

## Риски

Средний: меняется механика фильтров и структура `main.js`. Поэтому шаг 4 и baseline-скриншоты
обязательны, и делать это лучше **после** пункта 8 (git) — иначе откатывать нечем.

## Объём

Средний: новый генератор + правка `main.js` (фильтры, reveal-инициализация) + CSS.
