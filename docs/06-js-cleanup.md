# 6. Мёртвый код в `main.js` и `index.html`

**Статус:** сделано 22.11.2026 · **Риск:** низкий · **Объём:** ~20 строк

## Что было и что сделано

### 6.1 Недостижимая ветка `result.stored` — удалена

`main.js` читал `result.stored` и показывал «Заявка сохранена на сервере, но письмо
не отправлено». `send.php` такой ключ никогда не возвращал: ответ фиксированный —
`{'success': bool, 'message': string}`, `grep -c stored send.php` = 0. Ветка не
выполнялась ни разу, а обещание в интерфейсе существовало.

Выбран вариант **(B) — удалить ветку**, а не (A) писать заявки в файл:
по решению владельца PHP удаляется целиком, отправка переезжает на Node.js, поэтому
серверную часть мы не трогаем (см. `00-mail-not-configured.md`). Теперь JS обещает
только то, что сервер реально подтвердил: при `success:true` — «Заявка отправлена»,
при `503` или сетевой ошибке форма остаётся, показывается `role="alert"` с просьбой
позвонить, кнопка становится «Повторить отправку».

Следствие остаётся прежним и осознанным: **при отказе почты заявка теряется**.
Хранение заявок должен реализовать новый Node.js-бэкенд (журнал/БД вне docroot,
по политике хранения ПД), и только тогда ветку можно вернуть — уже по реальному
контракту ответа.

### 6.2 `regularPaintingImage` — удалена

`main.js:2` объявлял переменную и нигде её не читал (1 вхождение, 0 использований).
Осталась от версии, где картинка курса подставлялась отдельно.

### 6.3 `_subject` / `_template` — удалены

Два hidden-поля в форме (`index.html`) — наследие Formspree. `send.php` их не читает
(`grep` = 0), тема письма формируется на сервере. Удалены; honeypot `_honey` оставлен,
он используется.

Новый тест `tools/tests/test-form.mjs` подменяет `window.fetch` и проверяет обе ветки
интерфейса, включая регресс на возврат `stored`: даже если сервер пришлёт этот ключ,
надпись «сохранена» не появится.

## Критерии приёмки (выполнены)

- `grep -c regularPaintingImage` = 0, `_subject`/`_template` в HTML отсутствуют.
- Обещание «сохранена» исчезло из интерфейса вместе с несуществующей реализацией.
- Ветки успеха и ошибки проверены подменённым `fetch`, а не глазами.
