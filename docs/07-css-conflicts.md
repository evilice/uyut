# 7. Наслоение CSS-патчей: два измеренных дефекта и порядок-зависимость

**Статус:** не сделано · **Риск:** средний · **Объём:** средний, но только с baseline-скриншотами

## Постановка

`assets/css/styles.css` (40.6 КБ, 323 строки) склеен из четырёх исторических блоков
(базовый, «V3 MOBILE OPTIMIZATION» и два ранних патча логотипа героя). Порядок блоков
влияет на результат, поэтому правка «по месту» меняет не то, что правили.

Счётчики дублей по текущему файлу: `.hero-card-main{` — 6, `.work-visual{` — 6,
`.wrap{` — 4, `.brand-logo{` — 2. Блоков `@media` — 10 на 4 фактических брейкпоинта,
записанных двумя способами (`@media(max-width:700px)` ×5, плюс `@media (max-width: 650px)`
с пробелами).

### Поправка к первоначальному отчёту

Раньше я назвал это «конфликтом» и написал, что из трёх значений `.wrap` «работает только
последнее за счёт порядка». Это неточно: четыре `.wrap` лежат в **разных** `@media`
(строки 2, 4, 11, 142 → база, ≤1050, ≤650, ≤380), то есть это легитимные брейкпоинты.
Настоящие дефекты другие, и оба измерены в браузере.

### Дефект A. Ширина контента немонотонна

Замер `.wrap` по ширинам вьюпорта (Chromium, DPR2):

```
400px → 372px     390px → 362px     382px → 354px     381px → 353px
380px → 356px  *** прыжок вверх     379px → 355px     370px → 346px
```

При **сужении** окна с 381 до 380 контент становится **шире** (353 → 356 px). Причина:
боковые отступы уменьшаются 28px → 24px только на ≤380, то есть на мобильном классе
отступ меньше, чем на «планшетном», и формула `100% - 2*отступ` даёт скачок.

### Дефект B. Мёртвое правило логотипа в шапке

- `styles.css:158` (внутри `@media (max-width:380px)`) → `.brand-logo{display:block;width:126px;height:54px;…}`
- `styles.css:171` (внутри `@media(max-width:900px)`) → `.brand-logo{width:98px;height:45px}`

Оба матчат при 380px, а правило на строке 171 идёт **позже** и выигрывает. Замер:
на 380px и 320px логотип 98×45, то есть «126×54 для маленьких экранов» не применяется
никогда. Либо оно устарело, либо замысел был обратный и нарушен.

## План реализации

1. **Зафиксировать baseline — обязательный первый шаг.** Скриншоты 1920/1280/760/390
   с отключёнными `transition/animation`, `class="reveal"` видимым принудительно и
   `loading='eager'` на всех картинках. Обязателен **контрольный прогон** (два снимка
   одной версии) — он даёт 0 различий и отделяет реальные изменения от шума загрузки.
2. **Сгруппировать медиазапросы** по единому списку брейкпоинтов (1050 / 900 / 700 / 650 / 380)
   в одном порядке и одном написании, не меняя значений. Проверка — «различий в скриншотах 0».
3. **Схлопнуть дубли одного и того же селектора внутри одного брейкпоинта**
   (например 6 определений `.hero-card-main`, из которых часть относится к одному ≤650).
   Порядок правок: сначала убрать заведомо мёртвое, потом объединять живое.
4. **Решить дефект A:** отступы должны не расти при сужении. Вариант — привести ≤380
   к тем же 28px, что и ≤650 (скак исчезнет), либо поднять ≤650 до 30px. Это видимое
   изменение на 4px → требует решения владельца, а не «тихой правки».
5. **Решить дефект B:** спросить, каким логотип в шапке задуман на телефоне — 126×54 или
   98×45. По факту работает 98×45, значит либо удалить строку 158, либо перенести её ниже
   строки 171 и тогда размер станет 126×54 (визуальное изменение!).
6. Пересобрать скриншоты и diff. Допустимые отличия — только consciously принятые
   из п.4/п.5, всё остальное обязано дать 0.

## Критерии приёмки

- `grep -o '@media[^{]*' styles.css | sort | uniq -c` → каждое написание брейкпоинта один раз.
- Ни один селектор не объявлен дважды в одном и том же брейкпоинте.
- Ширина `.wrap` монотонна по всему диапазону 280–1920 (замер шагом 1px вокруг 380/650/1050).
- Diff скриншотов относительно baseline = 0, кроме согласованных п.4/п.5.
- Правила, которые никем не применяются, удалены (проверка: вычисленный размер совпадает
  с объявленным).
