# Генерация адаптивных картинок

Папка закрыта от веб-доступа (`tools/.htaccess` → 403). Скрипты запускаются на машине
разработчика, результат коммитится/загружается на хостинг как часть `assets/`.

## Когда запускать

После **любого** изменения фотографий в `assets/` (добавили мастер-класс, заменили фото
гостей, обновили сертификат). Порядок такой:

```bash
python3 tools/build-adapted-images.py    # перекодирует assets/img/*, пишет images.js
python3 tools/wire-adapted-images.py     # переставляет <picture> в index.html
```

`wire-adapted-images.py` идемпотентен: повторный запуск не удваивает обёртки, он снимает
прежнюю по маркеру `<!--@adapted …-->` и ставит новую. Проверено двойным прогоном с `diff`.

Если меняется только карта вариантов (например, поправили quality), а HTML трогать не нужно:

```bash
python3 tools/build-adapted-images.py --emit-only
```

## Что нужно сделать руками после добавления картинки

1. В `TABLE` (начало `build-adapted-images.py`) дописать исходник в нужную группу и
   измеренную CSS-ширину бокса. Ширины «красивыми числами» не брать: вариант = css-ширина
   бокса × DPR, и если посчитать меньше, картинка в лайтбоксе/карточке мыльнее, если
   больше — просто тяжелее.
2. Поднять `?v=` у `styles.css`, `main.js`, `images.js` в `index.html`: на них
   `Cache-Control: immutable, max-age=31536000`, без bump посетители с тёплым кэшем будут
   видеть старые файлы.

## Почему сделано именно так

- **AVIF + WebP, без JPEG-фолбэка.** Сайт уже требует `<dialog>` (Safari 15.4+ / Chrome 105+),
  а это требование свежее, чем WebP (Safari 14+). Значит `<img src>` в WebP — безопасный
  fallback, и держать ещё и копии в JPEG смысла нет.
- **`picture{display:contents}`** — иначе inline-бокс `<picture>` ломает верстку контейнеров.
  Из-за этого же дочерние селекторы вида `.box>img` перестают матчить (на матчинг
  `display:contents` не влияет), и в CSS такие правила переведены на `picture>img`.
- **Лайтбокс** сначала показывает уже декодированную миниатюру, затем подменяет src на
  full-вариант. Порядок важен: незагруженный `<img>` при `width:auto;height:auto` даёт box
  0×0 и смещение всего диалога (замеренный layout shift 0.105→0.194, после резерва через
  `aspect-ratio` + определённую ширину — 0.0016).
- **EXIF/ICC.** Применяется `exif_transpose`, а встроенный профиль конвертируется в sRGB:
  `master-classes-jpeg/photo-10.jpg` — Display P3, без конверсии цвета проседают
  (средняя дельта 3.0, максимум 30, 17.7% субпикселей с Δ>6).

## Результат на 2026-11-21

Загружаемый вес картинок главной: **21.4 МБ → ~1.0–1.25 МБ** (замер по `currentSrc`
выбранных файлов, 1920/DPR2 и 390/DPR3). На хостинге `assets/img` занимает 5.8 МБ.
Исходники в `assets/` не трогаются и остаются единственной полной копией — не удалять.
